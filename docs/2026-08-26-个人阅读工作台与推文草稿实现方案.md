## 1. 目标与边界

### 1.1 目标

Mars Reader 面向个人本地阅读，采用已确认的浅色四栏工作台：

```text
左侧导航 → 文章列表 → 中间原文/中文改写 → 右侧 AI 写推文
```

本阶段要完成：

1. 将当前可见的右侧 AI 伴读工作区替换为 AI 写推文工作区。
2. 在左侧导航增加“推文草稿”，并恢复每篇文章的最新草稿。
3. 保留原文、中文改写、手动生成中文改写和现有阅读行为。
4. 顶部只显示“最新”和“未读”；移除顶部“已改写资产”可见入口。
5. 将推文生成结果、人工编辑结果和写作方式保存为每篇文章的最新草稿。
6. 让有推文草稿的文章在 30 天数据库清理中受到保护，和收藏文章一致。
7. 保留 AI 伴读 API、数据表和代码，保证未来可以恢复。

### 1.2 不在范围内

- 不修改 RSS 来源、刷新频率和来源选择。
- 不修改中文改写的事实边界、数据模型或默认原文打开逻辑。
- 不删除 `chat_messages`、AI 伴读接口或相关后端逻辑。
- 不把推文草稿写入中文改写资产、公开资产 RSS 或资产统计。
- 不做推文历史版本、多人协作、公开发布或社交平台同步。
- 不做 Vercel、Turso、远端数据库或多用户产品化。
- 不在本阶段扩展批量中文改写 worker 的中止、断点续跑和跨进程恢复。
- 不生成或替换 Mars Reader Logo；暂时使用现有 Logo。
- 不修改 `开发路径图.md`。

## 3. 已批准的产品决定

### 3.1 信息架构

左侧导航保留“全部、未读、收藏、历史”和资讯、文章、播客来源，并增加“推文草稿”。推文草稿按 `updated_at DESC` 展示，显示文章标题、来源、写作方式、更新时间和正文摘要。

文章列表顶部只保留：

```text
最新 | 未读
```

旧的 `/assets/rewrite`、个人资产接口和公开资产 URL 保持可访问，用于兼容历史链接；它们不再作为主阅读工作台的顶部入口。

### 3.2 阅读与写作关系

- 文章默认仍打开原文。
- 中文改写仍是文章内部的显式标签和手动生成能力。
- 写推文不要求先生成中文改写。
- 原文是推文生成的事实参考材料。
- 已有中文改写可以辅助中文表达，但不是推文生成前置条件。

### 3.3 AI 写推文侧栏

右侧默认显示“AI 写推文”，包含：

- 当前参考文章
- 分享改写 / 润色原稿 / 观点补全
- 我的观点 / 原稿
- 本次写作要求（独立于用户原稿）
- 输出形式（短帖、长帖、编号要点、Thread）和语气（自然分享、克制分析、观点鲜明）
- 生成前的任务理解摘要和自然表达检查
- 可编辑的推文草稿
- 生成、停止、重新生成、复制
- 读取、生成、保存、失败状态

无当前文章时显示空状态；选择文章后加载该文章最新草稿。小屏幕采用浮动或底部面板，不造成横向滚动。

### 3.4 AI 伴读兼容

AI 伴读不再作为主阅读工作台默认可见区域，但以下内容保留：

- `chat_messages` 数据表
- 文章对话接口和流式接口
- 服务端模型调用和数据读取逻辑
- 可回滚的原有代码边界

“发给 AI 伴读”等前台入口在本阶段隐藏。隐藏不等同于删除；以后恢复伴读时不需要迁移数据。

## 4. 数据契约

### 4.1 `tweet_drafts` 表

实现时在 `lib/store.js` 的启动建表区增加（当前实际表在旧字段基础上包含 `task`、`format`、`tone`、`instruction`）：

```sql
CREATE TABLE IF NOT EXISTS tweet_drafts (
  entry_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  style TEXT NOT NULL DEFAULT 'share-rewrite',
  task TEXT NOT NULL DEFAULT 'share',
  format TEXT NOT NULL DEFAULT 'short',
  tone TEXT NOT NULL DEFAULT 'natural',
  user_input TEXT NOT NULL DEFAULT '',
  instruction TEXT NOT NULL DEFAULT '',
  draft TEXT NOT NULL DEFAULT '',
  source_content_hash TEXT NOT NULL DEFAULT '',
  model TEXT,
  provider TEXT DEFAULT 'deepseek',
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY(entry_id, user_id),
  CHECK(style IN ('share-rewrite', 'reflection')),
  CHECK(task IN ('share', 'polish', 'supplement')),
  CHECK(format IN ('short', 'long', 'bullets', 'thread')),
  CHECK(tone IN ('natural', 'restrained', 'pointed')),
  FOREIGN KEY(entry_id) REFERENCES entries(id) ON DELETE CASCADE,
  FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_tweet_drafts_user_updated
  ON tweet_drafts(user_id, updated_at DESC);

CREATE INDEX IF NOT EXISTS idx_tweet_drafts_entry
  ON tweet_drafts(entry_id, updated_at DESC);
```

语义：

- `(entry_id, user_id)` 唯一，永远只保存最新一版。
- `source_content_hash` 用来判断文章更新后草稿是否基于旧材料；旧草稿仍可展示，但响应标记为 `stale`，不静默覆盖。
- 推文草稿不是 `translation`、`rewrite` 或 `entry_ai_asset_contributions`。
- 删除文章或用户时通过外键级联清理草稿。
- 旧数据库启动时自动建表，不迁移、不重写历史资产。

### 4.2 清理保护

`ENTRY_RETENTION_PROTECTION_SQL` 增加：

```sql
OR EXISTS (
  SELECT 1 FROM tweet_drafts d WHERE d.entry_id = e.id
)
```

因此，存在推文草稿的文章按用户明确保留处理，免受 30 天存储清理删除；普通未收藏、无资产、无草稿文章仍遵守现有 30 天存储清理和 14 天前台展示策略。

## 5. HTTP 接口契约

### 5.1 读取当前文章草稿

```http
GET /api/entry/:id/tweet-draft
```

响应：

```json
{
  "draft": {
    "entryId": "…",
    "style": "share-rewrite",
    "userInput": "…",
  "draft": "…",
    "task": "share",
    "format": "short",
    "tone": "natural",
    "instruction": "…",
    "sourceContentHash": "…",
    "model": "…",
    "provider": "deepseek",
    "createdAt": 0,
    "updatedAt": 0,
    "stale": false
  }
}
```

没有草稿时返回 `draft: null`，不创建空记录。

### 5.2 生成并保存

```http
POST /api/entry/:id/tweet-draft
```

请求体：

```json
{
  "style": "share-rewrite",
  "task": "share",
  "format": "short",
  "tone": "natural",
  "userDraft": "可选的取舍方向或用户初稿",
  "instruction": "可选的本次写作要求",
  "systemPrompt": "浏览器 AI 设置中的推文系统提示词",
  "stylePrompt": "浏览器 AI 设置中的风格规则"
}
```

约束：

- `style` 只能是 `share-rewrite` 或 `reflection`；新客户端同时传 `task`，服务端保留旧 `style` 兼容映射。
- `share` 的输入可为空；`polish` 和 `supplement` 必须有用户输入。
- `format` 只能是 `short`、`long`、`bullets`、`thread`；`tone` 只能是 `natural`、`restrained`、`pointed`。
- 服务端限制用户输入 2000 字、系统提示词 8000 字、风格规则 6000 字。
- 服务端限制本次写作要求 800 字；不把 API Key、完整系统提示词或原文链接写入草稿记录。
- 服务端从当前文章重新读取材料和内容哈希，不信任客户端传入的文章正文或哈希。
- 调用 `requestAiConfig(req)` 读取浏览器 BYOK 配置。
- 生成成功后在同一请求中 upsert `tweet_drafts`。
- 不保存 API Key、完整系统提示词或原文链接。

### 5.3 手动保存

```http
PATCH /api/entry/:id/tweet-draft
```

请求体：

```json
{
  "style": "reflection",
  "task": "polish",
  "format": "short",
  "tone": "natural",
  "userInput": "用户自己的感想或初稿",
  "instruction": "本次写作要求",
  "draft": "用户继续编辑后的纯文本推文"
}
```

服务端重新确认文章存在和当前用户身份，限制草稿长度，更新 `updated_at`，并返回完整草稿记录。

### 5.4 列表与删除

```http
GET    /api/me/tweet-drafts?limit=100
DELETE /api/entry/:id/tweet-draft
```

列表只返回当前用户、未删除文章的最新草稿，按 `updated_at DESC` 排序。删除是幂等操作，成功后该文章不再出现在“推文草稿”导航和列表中。

### 5.5 错误契约

至少区分：

- 文章不存在：404
- 未登录：401；本地免登录身份初始化失败：503
- AI 配置缺失或非法：400/422
- 风格或输入不合法：400
- 上游 AI 失败：502
- 空响应或输出校验失败：502
- 保存失败：500

错误响应不包含 API Key、请求头、系统提示词全文或上游原始敏感信息。

## 6. 推文生成语义

### 6.1 分享改写

- 表达对原作者公共观点的认同。
- 用新的结构、顺序和语言重新表达同一个判断。
- 删除原作者私人经历、身份背景和个人示例。
- 原作者的“我/我们”不得变成 Mars Reader 用户的第一人称。
- 不补造替代案例。
- 正文不保留原文链接。

### 6.2 观点感想

- 用户写下的感想或推文初稿是主要材料。
- 文章只用于背景补充和事实核对。
- 只有用户明确写出的第一人称可以保留。
- 原作者的第一人称必须改成作者姓名、作者或明确主体。
- 没有用户输入时阻止生成，而不是让模型代写用户观点。

### 6.3 输出格式

- 默认短帖直接开头，围绕一个核心判断，使用 2–4 个短段落，每段 1–3 句。
- 长帖允许最多 6 个短段落；编号要点输出 3–5 条完整判断；Thread 输出 3–5 段连续编号。
- 只有用户选择 Thread 时才生成 Thread 编号，其他格式不主动生成 Thread 编号。
- 纯文本，不输出 Markdown 代码围栏、过程说明、自检清单或候选版本。
- 前端复制结果时不包含源码标记。

系统提示词默认值继续由 `lib/deepseek.js` 提供；用户可在“我的后台 → AI 设置”中修改系统提示词、分享改写规则和观点感想规则。服务端对空值、长度和纯文本输出做最后保护。

## 7. 前端状态与失败矩阵

| 场景 | 状态 | 是否写库 | 预期处理 |
| --- | --- | --- | --- |
| 文章没有草稿 | `idle` | 否 | 显示空编辑器和生成按钮 |
| 打开文章读取草稿 | `loading` | 否 | 显示读取中，禁止覆盖其他文章 |
| AI 生成中 | `generating` | 成功后写库 | 禁止重复生成，可点击停止 |
| 自动保存中 | `saving` | 是 | 显示保存中，防抖合并输入 |
| 已保存 | `saved` | 是 | 显示更新时间 |
| 文章内容已更新 | `stale` | 否 | 保留草稿并提示可重新生成 |
| AI 配置缺失 | `config-error` | 否 | 引导打开 AI 设置，保留用户输入 |
| AI 生成失败 | `error` | 否 | 保留用户输入和旧草稿，可重试 |
| 保存失败 | `save-error` | 否或旧版本 | 显示重试，不清空编辑内容 |
| 清空草稿 | `cleared` | 删除 | 从列表移除，编辑器恢复空状态 |
| 切换文章时旧请求返回 | 丢弃旧响应 | 不变 | 通过请求序号或 AbortController 防止串写 |

“停止”按钮在浏览器端终止等待和后续 UI 更新；同步上游请求已发出后，不声称 DeepSeek 服务端一定立即取消。

## 10. 浏览器验收清单

### 起始条件

- 构建/分支：`codex/local-hot-reload`
- 地址：`http://marsreader.localhost:18081/`
- 使用一个可复用浏览器标签页
- 桌面视口：1280×720 或更大，缩放 100%
- 移动视口：约 390px 宽
- 本地免登录身份可用；个人后台 AI 配置已保存
- 测试文章至少包含：一篇无推文草稿、一篇已有草稿、一篇已有中文改写、一篇可收藏文章

### A. 页面结构

1. 强制刷新首页并确认资源版本已更新。
2. 确认顶部只显示“最新”和“未读”。

## 11. 迁移、回滚与运维

### 11.1 迁移

- SQLite 启动时创建新表和索引。
- 不迁移已有中文改写、翻译、评论或对话。
- 不改旧公开 URL。
- 不保存 API Key。
- 不需要 Turso 或远端数据库。

### 11.2 回滚

- 前端工作区、导航和弹窗迁移可以整体回退。
- 后端新增接口可以独立关闭或回退。
- `tweet_drafts` 表即使保留也不会影响旧功能；不执行破坏性删除。
- 如 AI 写推文侧栏出现回归，可恢复原 AI 伴读可见面板，草稿数据仍保留。
- 如资产入口兼容出现问题，可恢复旧的可见入口而不改变底层数据。

### 11.3 运维

- 本地热部署继续使用现有脚本。
- 资源版本号随前端改动更新，避免旧 CSS/JS 缓存。
- 日志只记录脱敏的错误类型、文章 ID 和状态，不记录 API Key、提示词全文或完整文章正文。
- 生成和保存失败必须可观察，且不把半成品写入草稿表。

## 12. 被拒绝或暂不采用的方案

1. **删除 AI 伴读后端**：拒绝，因为需要为未来用户或回滚保留能力。
2. **继续使用推文弹窗**：拒绝，因为用户需要同时查看文章原文和自己的观点。
3. **把推文写入中文改写资产**：拒绝，会混淆资产统计、公开 RSS 和内容语义。
4. **只用 localStorage 保存草稿**：拒绝，因为刷新、浏览器清理和本地多设备访问都会丢失最新草稿；现有 SQLite 已能满足持久化。
5. **增加 Turso 或远程数据库**：拒绝，本阶段仍是本地个人使用。
6. **现在做推文版本历史**：拒绝，先只保留最新一版，降低维护成本。
7. **立即改动 `开发路径图.md`**：拒绝，本报告记录当前已批准路径，但路线图仍由用户单独控制。

## 13. 未解决风险

1. 文章内容更新后旧草稿可能不再适合当前材料；通过 `source_content_hash` 标记，但不自动重写用户内容。
2. “停止”只能可靠停止浏览器等待，不能保证已发出的同步上游请求立即取消。
3. 推文草稿保护文章会减少清理数量；这是用户明确选择的“主动保留”语义。
4. 用户自定义系统提示词可能降低生成质量；服务端保留长度、空值和输出格式保护，但不替用户判断提示词内容。
5. 现有工作树有未提交改动，若不先区分本阶段 diff，可能把历史工作误认为本次实现结果。
6. AI 伴读隐藏后，依赖其可见入口的用户暂时无法从主界面进入；恢复入口需要后续明确产品决定。
