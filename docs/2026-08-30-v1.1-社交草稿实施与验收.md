## 目标与判断

把右侧“AI 写推文”从三段式写作配置器收敛为一个简单任务：读取当前文章重点和观点，结合用户临时写下的想法，生成一版可继续编辑的社交媒体草稿。

这样做的理由是，文章与临时想法不是互斥的写作模式。用户可以不写想法，让文章承担主要材料；也可以补充自己的判断，让自己的判断决定取舍，文章负责提供事实和论证。

## 已确认的产品契约

### 界面

- 保留当前文章引用提示。
- 只保留一个有明确标签的可选输入框，用于临时观点、想强调或略过的内容。
- 只保留一个生成按钮。
- 草稿保持可编辑，并保留停止、重新生成、复制、清空和自动保存。
- 移除三个写作起点、短帖或长帖、三种语气、本次写作要求和 1/2/3 步骤轨道。
- AI 设置中只保留一个可编辑的推文系统提示词。

### 生成语义

- 没有临时想法时，从文章的公共信息中选择最值得分享的一条主线，不把原作者的经历写成用户经历。
- 有临时想法时，优先保留用户的判断、立场和人称，文章只补充明确支持的事实、背景和论证。
- 用户想法与文章不一致时，不擅自把两者改成一致，也不替用户发明结论。
- 输出更通俗、有趣、有情绪，可以适度夸张表达力度，但不能夸张事实。
- 多分段，一般每段 1 到 2 句，最多 3 句。
- 默认使用自然段；只有多个独立观点确实适合并列时，才在局部使用 `• ` 列表。列表前后仍可使用自然段。
- 不保留原文链接，不复制原文，不输出 Markdown 标题或代码围栏。
- 保留此前可迁移的写作能力，包括先抓核心冲突、讲清机制、给具体信息、减少空话和形成有力收束；不接入 Codex Skill、作者人格、范例库或长期声音档案。

### 数据与兼容

- 新生成记录使用统一任务标识。
- 旧版 `share`、`polish`、`supplement` 草稿继续可读取、编辑、保存和重新生成。
- 旧草稿中的临时观点与额外写作要求在统一输入中无损呈现，数据库不做破坏性迁移。
- 保留用户已自定义的系统提示词。只有仍在使用已知旧默认值时，前端才升级到新的默认提示词。
- 旧模式相关浏览器存储和数据库字段暂不删除，作为回滚边界。

## 状态与失败处理

| 状态 | 界面行为 | 数据行为 |
| --- | --- | --- |
| 未选择文章 | 禁用生成，提示先选择文章 | 不发送请求 |
| 正在载入旧草稿 | 禁用输入和生成，显示载入状态 | 不覆盖当前文章之外的数据 |
| 空想法 | 允许生成文章主导的草稿 | 保存空想法 |
| 正在生成 | 显示进度和停止按钮，禁用重复生成 | 停止时中断当前请求，不清除旧草稿 |
| 生成失败 | 保留输入和旧草稿，显示原始错误 | 不写入失败结果 |
| 自动保存中 | 显示保存状态 | 只更新当前用户和当前文章的唯一草稿 |
| 保存失败 | 保留本地编辑内容并显示错误 | 不宣称已保存 |
| 文章已更新 | 显示内容已更新提示 | 旧草稿保持可编辑，可由用户重新生成 |
| 清空 | 点击后清空并显示结果 | 删除当前用户当前文章的草稿，不影响文章和其他草稿 |

## 边界、依赖与回滚

- 不新增依赖、接口或数据库表。现有草稿表的任务约束只做兼容性扩展，允许新值 `compose`，原字段和原数据完整保留。
- 沿用现有 AI 配置、草稿接口、登录权限、请求中止和保存机制。
- 不修改中文改写、AI 伴读、RSS、收藏、历史和草稿目录行为。
- 回滚时可恢复本分支的前端、后端和测试改动；由于旧字段和旧浏览器键保留，不需要回滚数据。
- 发布阶段同步更新 README 与项目版本；提交、合并、标签和推送以 `v1.1.0` 发布授权为边界。

## 人工浏览器验收清单

验收状态保持 `PENDING`，直到用户明确记录 `PASS`。

### 准备

- 分支：`codex/v1.1-social-draft`
- 当前服务已经启动。如需重启，使用 `/Applications/ChatGPT.app/Contents/Resources/cua_node/bin/node scripts/hot-server.js`；本机 `/usr/local/bin/node` 是不可在当前 arm64 环境运行的 x86_64 版本，直接执行默认 `npm run dev:hot` 前需要先修正 Node 路径。
- 地址：`http://marsreader.localhost:18081/`
- 默认只复用一个内置 Browser 标签页。
- 桌面视口先用 1440 × 900、100% 缩放，再检查 1280 × 800 和窄屏 820 × 900。
- 使用一篇有明确观点且正文已加载的文章；准备一段与文章一致的临时想法，以及一段与文章有分歧的临时想法。

### 顺序操作与预期

1. 打开文章并展开右侧写作台。确认文章仍可阅读，右侧只出现文章引用、一个可选想法框、一个生成按钮和草稿区，没有写作模式、长度、语气或 1/2/3 步骤。
2. 不填写想法直接生成。确认按钮进入生成中状态，可停止；完成后草稿以文章公共观点为主，不冒充原作者经历，不含原文链接。
3. 检查成稿结构。确认文风通俗、有趣、有情绪，事实没有被夸大；每段最多 3 句，自然段与必要的局部 `• ` 列表可以共存。
4. 填入与文章一致的想法并重新生成。确认用户判断决定重点，文章只补充事实和机制。
5. 填入与文章有分歧的想法并重新生成。确认系统不擅自抹平分歧，也不虚构用户经历或结论。
6. 在草稿框中手动编辑，切换到另一篇文章再切回。确认自动保存和每篇文章独立草稿有效。
7. 打开一篇 v1.0 旧草稿。确认原有临时观点和写作要求都能在统一输入中看到，草稿可继续编辑、保存和重新生成。
8. 测试复制、停止、重新生成和清空。确认停止不删除旧稿，复制内容与草稿一致，清空只影响当前文章。
9. 打开左下角设置中的 AI 设置。确认只保留一个推文系统提示词；修改后刷新页面仍保留，恢复默认只恢复这一项，不影响中文改写和 AI 伴读。

### 交互、可访问性与布局

- 用 Tab 依次访问想法框、生成、停止或复制或清空和关闭侧栏；焦点可见，顺序符合阅读顺序。
- 检查输入框标签始终可见，placeholder 不是唯一说明；按钮禁用、生成中和错误状态可辨认。
- 检查长文章标题、长想法和长草稿下的换行、滚动和调整高度，不出现横向滚动或控件遮挡。
- 在三个视口检查侧栏开合、页面纵向滚动、草稿框内部滚动和窄屏上下布局，文章与写作台都能继续操作。
- 检查无文章、载入、生成、停止、接口错误、保存错误、空草稿和文章已更新状态，提示清楚且不会丢失可恢复内容。
- 检查浏览器控制台无新增错误，生成和保存请求无意外重复，失败请求不被展示为成功。
