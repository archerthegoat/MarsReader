# Mars Reader 个人化阅读与推文改写计划

## 文档状态

- 状态：已获用户确认，作为本轮实现边界
- 确认日期：2026-08-25
- 适用分支：`codex/local-hot-reload`

- 本轮不修改 `开发路径图.md`，不提交、不推送、不部署

## 1. 目标与边界

Mars Reader 当前按个人本地使用优先进行简化，同时保留原项目中对其他读者有价值的 AI 伴读能力。此次改动的目标是：

1. 让已经批准的个人化前台隐藏、置顶和顶部导航调整真正生效。
2. 在产品层把中文翻译/中文改写统一表达为“中文改写”，避免用户在多个页面看到不一致的概念。
3. 增加一个独立于 AI 伴读栏的“写成推文”工具，使用个人后台配置的 DeepSeek/BYOK 配置。
4. 让推文系统提示词和两种写作方式规则在“个人后台 → AI 设置”中配置；推文功能页只保留对应的用户输入和写作方式，并提供一个不带明显 AI 腔的默认版本。
5. 推文第一版只作为临时草稿，不保存为资产、不进入 RSS、不增加数据库类型。
6. 文章级中文改写显示清晰的生成状态；批量改写的完整后台队列、中止和持久化改造暂缓。

不在本轮范围内：

- Product Hunt 来源逻辑和内容质量策略
- AI 伴读栏、伴读标签、伴读提示词、伴读对话存储和布局
- 多用户产品化、公开注册、远端数据库和部署架构
- 推文历史版本、推文公开资产和推文 RSS
- 批量改写 worker 的完整取消协议、断点续跑和跨进程持久化

## 2. 已核对的当前事实

### 2.1 当前工作树和资源缓存

本分支已有未提交的个人化改动，涉及来源隐藏、7 天展示保留、300 条默认列表、置顶和本地热部署等文件。不得重置或覆盖这些已有改动。

`public/index.html` 当前使用带版本号的静态资源：

- `/styles.css?v=164`
- `/lucide-icons.js?v=2`
- `/app.js?v=164`

`server.js` 对带版本号的静态资源使用长期 immutable 缓存。此前 HTML 已经加入部分 `hidden` 属性，但浏览器可能继续使用旧版 JS/CSS，因此本轮必须同时更新资源版本号，并让热服务器监听 Lucide bundle。

### 2.2 当前资产模型

当前底层存在两类 AI 资产：

- `translation`：结构化双语翻译数据
- `rewrite`：中文改写正文

用户已确认产品定义上统一称为“中文改写”。本轮不物理迁移历史数据库记录，而是在展示、统计和导航层统一语义；打开历史资产时仍根据真实数据结构渲染。

### 2.3 当前 AI 配置边界

个人后台 AI 配置通过浏览器请求头传递给服务端，使用 `lib/request-ai-config.js` 解析。已有中文翻译、中文改写和文章对话接口均复用这条 BYOK 路径。API Key 不应写入 Git、数据库或日志。

### 2.4 当前改写执行边界

文章页的中文改写是同步请求，前端已有 `rewriteLoading` 和 `rewriteGenerating` 状态，但可见状态不足。批量改写通过 `scripts/refresh-worker.js` 在后台执行；本轮不扩展 worker 协议，只补文章级状态。

## 3. 已确认的设计决策

### 3.1 前台入口隐藏

前台隐藏：

- 读者提交来源
- 提交链接按钮
- 文章页收录到本站按钮
- 热门入口
- 贡献榜入口

历史投稿、管理员审核接口和兼容路由不删除。普通来源列表和普通文章列表必须排除隐藏来源；管理员需要时仍可读取明确的历史来源。

### 3.2 置顶来源与图标

置顶来源继续显示在来源列表最前面。置顶按钮使用 Lucide `MapPin` SVG，不使用 emoji。静态资源版本号和热监听列表必须同步更新，避免图标修改只存在于磁盘而不出现在运行页面。

### 3.3 顶部信息架构

顶部只保留一行：

```text
最新 | 已改写资产 | 未读
```

原来的第二行“文章列表 / 已改写资产”不再作为顶部导航展示。

“已改写资产”是统一后的中文改写入口。新入口优先筛选 `rewrite`，历史 `translation` 记录可在资产聚合展示中兼容出现，但不能破坏原有资产打开路径。热榜和贡献榜的底层路由暂不删除。

### 3.4 中文改写统一命名

产品展示层统一使用“中文改写”：

- 文章阅读页：中文改写
- 顶部导航：已改写资产
- 公开资产筛选：改写
- 个人后台资产分类：改写
- 复制、生成、缓存和失败状态：中文改写

内部 `translation` 和 `rewrite` 字段继续保留，以兼容已有数据库、API 和公开链接。不得未经批准删除或批量重写历史资产。

### 3.5 AI 伴读栏保持不变

不修改 `#agent-pane` 的结构、标签、提示词、对话逻辑、流式输出、配置入口和状态。推文功能不能新增为 AI 伴读栏中的 tab。

推文入口放在文章中文改写区域，打开独立的推文功能面板或弹窗。该面板与 AI 伴读栏是两个独立功能边界。

推文面板提供两个固定写作方式：

- `分享改写`：表示用户认同原作者的观点和思考。以文章中的公共观点、论证链条和非私人事实为主，用新的结构、顺序和语言重新表达同一个判断；删除原作者的个人经历、私人场景、身份背景和亲自做过的示例，不改写成用户经历，也不凭空补例子。正文不保留原文链接。
- `观点感想`：以用户自己写下的感想或推文草稿为主，文章只用于事实核对和背景参考；用户的第一人称可以保留，原作者的“我/我们”必须改成作者或具体姓名，不得把原作者经历混入用户表达。

默认选择 `分享改写`。分享改写的输入是可选的取舍方向；观点感想必须先填写用户自己的感想或初稿，风格按钮由服务端固定规则落实，而不是只改变前端文案。

### 3.6 推文草稿暂不持久化

推文生成结果只存在当前页面状态中，可以复制或重新生成，但：

- 不写入文章资产表
- 不计入“已改写资产”统计
- 不进入公开资产 RSS
- 不增加 `tweet` 数据库类型
- 不影响 AI 伴读消息和中文改写资产

如果以后要保存推文历史，必须另行设计 `tweet` 资产模型、权限、公开性和清理策略。

### 3.7 批量改写暂缓复杂改造

本轮不新增批量 worker 的中止 IPC、断点续跑、跨进程任务持久化或复杂进度面板。批量改写仍按目前的个人手动使用方式运行。

本轮只增加文章级中文改写状态：待生成、读取材料、生成中、已保存、显示缓存、失败。生成期间防止重复点击，切换文章后不得用旧请求结果覆盖当前文章。

## 4. 推文系统提示词

现有卡兹克 Skill 面向中文公众号长文，并明确不直接用于推特等短内容。本轮同时参考 `content-repurposer-sms` 的“提取可独立成立的洞见、按平台重组、避免复制粘贴”原则，以及 `twitter-x-posts` 的“单条 X 帖子、直接开头、核心价值、平台限制”原则，编写专门的推文系统提示词。默认提示词作为服务端默认值和个人后台 AI 设置的可编辑初始值；分享改写和观点感想的风格规则也在个人后台分别可编辑，推文功能页不直接展示系统提示词。

系统提示词必须固定以下边界：

- 区分 Mars Reader 用户、文章作者和文章中被提到的人；文章作者的“我/我们”不能变成用户的“我”。
- 分享改写是对原作者公共观点的同观点重写，不是新闻摘要；删除原作者的私人经历、身份背景和个人示例，不补造替代案例，正文不保留原文链接。
- 观点感想以用户自己的感想或草稿为主，文章只用于事实核对和背景参考；只有用户明确写出的第一人称才可保留。
- 使用短段落、直接开头、自然口语和有变化的句子节奏，避免报告腔、模板套话和明显的 AI 味。
- 输出一版可编辑的纯文本单条 X 帖子，不输出过程、候选、自检清单、Markdown 代码围栏或 Thread 编号。

系统提示词配置要求：

- “个人后台 → AI 设置”显示推文改写系统提示词配置
- 同一处分别显示“分享改写规则”和“观点感想规则”
- 提供“恢复默认”按钮
- 在浏览器本地保存用户修改的系统提示词和两种风格规则
- 限制长度，防止异常超长请求
- 服务端在缺少或非法提示词时回退到默认提示词
- 推文功能页不显示系统提示词，只显示写作方式和对应的输入区
- 不影响中文改写和 AI 伴读的系统提示词

## 5. 接口与数据契约

### 5.1 推文草稿接口

```http
POST /api/entry/:id/tweet-draft
```

请求体：

```json
{
  "style": "share-rewrite",
  "userDraft": "分享改写时为可选取舍方向；观点感想时为用户自己的感想或推文草稿",
  "systemPrompt": "用户在个人后台 AI 设置中配置的推文系统提示词",
  "stylePrompt": "用户在个人后台配置的当前写作方式规则"
}
```

约束：

- 必须存在文章
- `style` 只能是 `share-rewrite` 或 `reflection`，非法值回退到 `share-rewrite`
- 分享改写的 `userDraft` 可为空；观点感想的 `userDraft` 必须非空且长度受限
- `systemPrompt` 可为空，服务端回退默认值
- `stylePrompt` 可为空，服务端按当前风格回退默认值
- 使用 `requestAiConfig(req)` 读取浏览器 BYOK 配置
- 文章内容、用户输入、系统提示词和风格规则必须分离传入，文章正文只作为材料
- 分享改写不向模型提供原文链接，并对最终输出做链接过滤；观点感想可以保留链接作为参考
- 不保存请求中的 API Key、提示词或生成结果

响应体：

```json
{
  "draft": "纯文本推文草稿",
  "model": "实际使用的模型",
  "provider": "deepseek"
}
```

失败状态需要区分：文章不存在、未配置 AI、配置不合法、AI 请求失败、空响应和内容校验失败。

### 5.2 中文改写状态

文章级状态只在前端显示，不新增后台任务表。至少覆盖：

| 状态 | 触发条件 | 用户可见行为 |
| --- | --- | --- |
| `idle` | 未生成或页面刚打开 | 显示生成按钮 |
| `loading` | 正在读取已有改写 | 显示读取中，不重复触发 |
| `generating` | 用户点击生成 | 显示生成中，禁用重复点击 |
| `saved` | 新改写成功保存 | 显示已保存，允许重新生成 |
| `cached` | 服务端返回缓存 | 显示已显示缓存改写 |
| `error` | 请求失败 | 显示错误，可重试 |

## 6. 状态和失败矩阵

| 场景 | 预期状态 | 是否写库 | 处理方式 |
| --- | --- | --- | --- |
| 推文未配置 AI | 配置缺失 | 否 | 打开个人 AI 设置提示 |
| 推文生成中 | 生成中 | 否 | 禁用重复点击 |
| 推文成功 | 已生成草稿 | 否 | 展示纯文本并允许复制 |
| 推文请求失败 | 生成失败 | 否 | 保留当前用户输入，允许重试 |
| 中文改写未生成 | 待生成 | 否 | 手动点击生成 |
| 中文改写生成中 | 生成中 | 请求成功后写库 | 当前文章按钮禁用 |
| 中文改写返回缓存 | 已显示缓存 | 不新增重复记录 | 显示缓存状态 |
| 中文改写失败 | 失败 | 不保存不完整结果 | 显示可重试错误 |
| 页面切换文章 | 当前请求仍在途 | 按现有接口处理 | 丢弃旧文章对当前 DOM 的更新 |
| 普通浏览器刷新 | 重新读取页面状态 | 不改变后台任务 | 不显示过期的生成中状态 |
| hot-server 重启 | 进程级中断风险 | 已写入结果保留 | 不声称任务跨进程继续 |

## 7. 被拒绝或暂不采用的方案

### 7.1 把推文放进 AI 伴读栏

拒绝原因：会改变用户已经认可的 AI 伴读界面，也会影响后续使用伴读功能的其他用户。

### 7.2 把推文保存为 `rewrite` 资产

拒绝原因：会让“已改写资产”同时包含文章改写和社交媒体草稿，造成统计、公开 RSS 和个人后台分类混乱。

### 7.3 现在就做完整的批量任务系统

拒绝原因：批量中文改写不是当前核心功能，复杂 worker 中止、持久化和恢复会增加本地部署维护成本。

### 7.4 立即物理合并 `translation` 与 `rewrite` 数据

拒绝原因：两者历史内容结构不同，直接迁移会影响已有公开链接、API 响应和文章详情渲染。先统一产品语义，保留底层兼容边界。

## 9. 浏览器验收清单

### 起始条件

- 构建/分支：`codex/local-hot-reload`
- 地址：`http://marsreader.localhost:18081/`
- 使用一个可复用浏览器标签页
- 桌面视口约 1440×900，缩放 100%
- 已配置个人后台 DeepSeek AI 配置
- 浏览器控制台和网络面板可在需要时查看

### A. 前台隐藏和缓存

1. 打开首页，执行一次普通刷新，再新开同一地址的标签页确认资源版本生效。
2. 检查左侧栏，确认看不到贡献榜和热门。
3. 确认看不到读者提交和提交链接入口。
4. 检查来源列表，确认隐藏来源不出现。
5. 检查置顶来源，确认图标是线性 SVG 图钉，不是 emoji。
6. 在控制台检查没有 `app.js`、`styles.css` 或 `lucide-icons.js` 的 404。
7. 检查网络响应的资源 URL 已包含新的版本号。

### B. 顶部和资产语义

1. 确认顶部只有“最新、已改写资产、未读”三个入口。
2. 确认没有第二行“文章列表 / 已改写资产”。
3. 点击“已改写资产”。
4. 确认列表标题和筛选文案统一使用中文改写/改写资产。
5. 确认历史可用的中文翻译/改写记录可以打开，不出现空页面。
6. 进入个人后台的资产区域，确认分类名称与顶部入口一致。
7. 点击一条资产，确认能回到对应文章和正确内容。

### C. AI 伴读回归检查

1. 打开一篇文章。
2. 确认右侧仍只有原有 AI 伴读和隐藏的划线评论结构。
3. 确认没有新增推文 tab。

## 10. 迁移、回滚和维护

### 迁移

- 不新增数据库表
- 不删除历史 `translation` / `rewrite` 数据
- 不修改旧公开资产 URL
- 仅增加前端展示映射和推文临时状态
- 用户自定义推文系统提示词只保存在浏览器本地

### 回滚

- 静态资源版本号可以回退
- 推文接口和 UI 可以独立移除
- 不需要数据库回滚
- 文章级状态只影响前端展示，不改变改写存储协议
- 如果统一资产展示出现兼容问题，可回退展示映射而不触碰底层数据

## 11. 未解决风险

1. 历史 `translation` 与 `rewrite` 的内容结构不同，统一展示需要逐条验证渲染和打开路径。
2. 用户可以在个人后台编辑系统提示词，过度修改可能降低输出质量；服务端仍需保留长度、空值和纯文本输出保护。
3. 浏览器刷新不会取消服务器进程中的批量任务，但 hot-server 进程重启仍然可能打断 worker；本轮不承诺跨进程任务恢复。
4. 文章级改写本轮仍是同步请求，真正的单篇取消需要后续单独设计。
5. 推文不持久化意味着刷新后草稿会丢失，这是本轮明确接受的取舍。
6. 分享改写按用户要求不自动保留原文链接，因此生成结果不会自动提供来源归因；发布前是否需要人工注明来源，由用户自行判断和处理。
